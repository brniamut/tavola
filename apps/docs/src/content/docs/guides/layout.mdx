Users arrange the columns themselves:

- **Show, hide and order** in the column picker behind the Columns button. See below.
- **Reorder** by dragging a header's grip, which appears on hover, or in the column picker. Columns move within their region: pinned to the start, unpinned, or pinned to the end.
- **Resize** by dragging a header's right edge. Double-click the edge to restore the default width.
- **Pin and unpin** from a header's menu. Pinned columns stay in place while the table scrolls sideways; row actions always stay at the very end.
- **Density**: compact, normal or comfortable rows, from the button next to Columns.

You set the starting point per column with `pin`, `hidden`, `size` and `defaultDensity`, and lock what users may change with `hideable`, `reorderable` and `resizable`.

## The column picker

The Columns button opens a dialog with two panes:

- **Shown**, on the left: the visible columns in table order. Drag a row by its handle, or use the arrows, to change the order; with the keyboard, focus the handle, press Space, move with the arrow keys and press Space again (Escape cancels). The cross hides a column. Each row shows the column's group and why it behaves differently: always shown, pinned, or hidden because the table is too narrow.
- **Add columns**, on the right: the hidden columns, grouped and searchable. The plus adds a column at the end of the list.

Focus follows the column: hiding one moves focus to its plus button and adding one to its cross, so either is undone with one keystroke. Nothing changes until Apply; Cancel or Escape drops the changes, and "Restore defaults" goes back to the columns as you defined them.

Give columns a `group` when a table has many of them. The picker groups the columns to add by it, shows it under the header, and the search finds columns by it:

```ts
col.text('street', { group: 'Address' }),
col.text('city', { group: 'Address' }),
col.number('creditLimit', { group: 'Billing' }),
```

While columns are hidden, a line above the table says how many are visible, with a button that opens the picker. Turn it off with `columnSummary={false}`.

### Presets

Offer common column sets as one-click buttons. A preset shows its columns in the given order and hides the rest, except columns with `hideable: false`. An "All columns" button is always there.

```tsx
<DataTable
  columnPresets={[
    { label: 'Contact', columns: ['name', 'email', 'phone', 'city'] },
    { label: 'Billing', columns: ['name', 'creditLimit', 'balance', 'paymentTerms'] },
  ]}
  /* ... */
/>
```

### Saved views

Users can save the current arrangement under a name and load it later. A view keeps the columns (order, visibility, pins, widths) and the current filters, sort and search, and opens on the first page. Saving under an existing name, ignoring case and accents, replaces that view.

Where views are kept:

- With an `id`, in `localStorage` under `tavola:<id>:views`.
- With `views` and `onViewsChange`, wherever you keep them, for example per user on your server:

```tsx
const [views, setViews] = useState<SavedView[]>(initialViews);

<DataTable
  views={views}
  onViewsChange={(next) => {
    setViews(next);
    saveViews(next);
  }} /* ... */
/>;
```

- With neither, the picker leaves out the save fields.

A view saved before you changed the columns still loads: like the saved layout, it is checked against the current columns.

## Remembering the layout

With an `id`, the column order, visibility, pinning, widths, density and page size are saved in `localStorage` under `tavola:<id>`.

```tsx
<DataTable id="people" /* ... */ />
```

The saved layout is safe across releases of your app:

- It is read after mount, so server rendering and hydration are not affected.
- It is checked against the current columns. Columns you removed are dropped, columns you added appear in their default place, and widths are clamped to the column limits.
- It is versioned, so a future change in the storage format starts from the defaults instead of breaking.
- When storage is unavailable (private mode, full), the table works and simply does not remember.

## Narrow screens

Give columns a `priority` and they hide automatically when the table is narrower than its columns, the highest number first, until the rest fits. Columns without a priority never hide by themselves:

```ts
col.text('name'), // always shown
col.text('email', { priority: 1 }), // hidden last
col.date('joined', { priority: 2 }), // hidden first
```

The calculation uses the column widths, not the rendered page, so columns do not flicker in and out. Columns hidden this way are not saved, and a user can still show one from the column picker; that choice wins.
